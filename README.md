# 校园主干道绿化过程式布置台

面向园林/景观课程的过程式绿化布置教学系统。教师按课程布置题目（参数范围 + 随机种子），
学员在 3D 场景中绘制道路、调参生成方案、提交核对；系统自动按题目范围给部分分，
教师复核打分，最后汇总成绩与典型错误。

技术栈：**原生 TypeScript + Web Components（零框架）+ Babylon.js（Thin Instance 实例化渲染）+ Vite**。

## 运行

```bash
npm install
npm run dev        # 开发服务器
npm test           # 无头 Chrome 端到端测试（27 项断言）
npm run build      # 类型检查 + 生产构建
```

测试需要本机安装 Chrome（默认读取 `C:\Program Files\Google\Chrome\Application\chrome.exe`，
可在 `tests/e2e.mjs` 顶部修改路径）。

## 功能与实现对照

| 需求 | 实现 |
| --- | --- |
| 先画中心线和路缘，再设参数 | 绘制工具在地面点击生成控制点，Catmull-Rom 样条 + 等弧长重采样生成中心线，自动派生路面与两侧路缘 |
| 路宽/树间距/树种比例/花坛长度/路灯间隔/季节 | 全部为响应式参数面板滑块，题目范围实时校验、越界标红 |
| 同种子的树、灌木、灯位完全一致 | 每个对象的随机量由 `hash(种子, 类型命名空间, 段号)` 派生 mulberry32 流，站位按段内固定序号生成（`src/core/rng.ts`、`generator.ts`） |
| 手动挪树自动锁定，重生成原地不动 | 挪动即写 `locked`，`regeneratePlacements` 永远保留锁定项与重算范围外的项（金色圆环标识） |
| 只重算受影响区段 | 道路按题目分段长度切段，框选得到段集合，仅这些段走生成器，其余对象原样保留 |
| 框选一段路单独重生成 | 屏幕矩形反投影地面包围盒，命中采样点所属段；工具栏「选中段重生成」 |
| 实例化渲染、300+ 不掉帧 | 全部绿化对象走 Thin Instance，每类 1 个 draw call；千树场景实测约 34 个 draw call/帧 |
| 夏冬两季叶色与树冠密度 | 冬季树冠缩放 ×0.62、叶色转枯黄、草地/灌木/花坛同步换色，仅切换实例缓冲数据 |
| 导出布置清单 | CSV（带 UTF-8 BOM，Excel 直开，含参数摘要与逐项坐标/锁定状态）+ JSON |
| 俯视截图 | 按道路包围盒取景的 1600×1200 PNG，自动下载 |
| 自动核对给部分分 | 范围内满分，范围外按偏离比例线性给分；树种比例按目标比例 ± 容差核对（`src/core/grading.ts`） |
| 教师复核 + 成绩/典型错误汇总 | 复核弹窗写最终分与评语；汇总页含分数段分布、自动分/复核分均值、典型错误频次条形图 |

## 目录结构

```
src/
  core/        纯算法：确定性随机、道路几何、布置生成器、核对评分、导出、持久化
  state/       发布订阅式全局 store（无框架）
  babylon/     SceneEngine：道路渲染、Thin Instance、拾取拖动、框选、截图
  components/  六个自定义元素（app-shell / viewport-3d / param-panel /
               teacher-panel / grading-panel / workflow-guide）
tests/e2e.mjs  Playwright(core) + 本机 Chrome 的全流程端到端测试
```

## 关键设计说明

- **分段生成**：道路按 `segmentLength` 切段，生成器以段为单位工作；段内站位的局部序号
  不随其它段变化，因此改参数后重算任意段都不会波及其它段的随机结果。
- **锁定语义**：锁定对象保留生成时的 id 与坐标，重生成时同 id 新对象跳过；
  可在数据层（localStorage）与表现层（金色锁定环）同时观察。
- **持久化**：控制点、参数、布置（含锁定态）、成绩均存 localStorage，刷新不丢；
  道路几何是控制点的纯派生数据，加载时重建。
